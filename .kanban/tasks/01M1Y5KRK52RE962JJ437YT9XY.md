## What

Several documents state the old tool policy in words. After the gates move, each states something that is not true. Correct them. Do this task last, because it records what the other tasks decided.

Files to change:
- `builtin/validators/swift/VALIDATOR.md`
- `builtin/validators/swift/rules/access-control.md`
- `builtin/validators/code-hygiene/VALIDATOR.md` — the table row that reads `| idioms-swift | swiftformat --lint, 29 named rules | ... |`, and the row that names the exemption directive
- `builtin/validators/code-hygiene/rules/disallowed-constructs-swift.md` — the part that states the force rules stay OFF in a test target BECAUSE `idioms-swift` enables two swiftformat rules

`builtin/validators/swift/VALIDATOR.md` states this today:

> Two tool rules of `builtin/validators/code-hygiene/` carry the deterministic half: `idioms-swift` runs swiftformat over every changed Swift file, and `disallowed-constructs-swift` runs swiftlint.

Write instead that `idioms-swift` and `missing-docs-swift` run the toolchain's `swift format`, and that `disallowed-constructs-swift`, `function-length-swift` and `magic-numbers-swift` run swiftlint, and that `dead-code-swift` runs periphery. Keep the rule that divides the two sets, because it does not change: **if a tool can decide it, the tool owns it.**

The same file says formatting concerns belong to `swift-format`. That sentence is correct and becomes clearer, because `swift format` is now the one tool. Make the spelling the same everywhere: the command is `swift format`.

Every document that names the exemption directive `// swiftformat:disable:next` must name `// swift-format-ignore` instead, for a rule the toolchain now runs.

Do not change any rule that this move does not touch.
